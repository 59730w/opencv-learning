# Day59：农业机器人作物行视觉感知——开源基线审查、目标契约与坐标定义

## 1. 今天完成什么

Day1-Day58 已经覆盖 OpenCV、PyTorch、目标检测、语义分割、C++、CMake、ONNX Runtime、量化与性能诊断。Day59 不再继续扩展 ONNX Runtime 优化，而是把已有能力迁移到导师可能相关的农业机器人图像处理与机器视觉方向。

今天只推进新项目的第一道门：

```text
开源项目审查 → 明确任务与声明边界 → 定义坐标和输出 → 固定指标与证据角色
```

今天不下载完整数据、不训练模型、不实现机器人控制。13秒的项目视频已经足以提供“输入图像最终怎样变成方向/偏移输出”的直观印象；视频展示不是算法有效性的证据。

## 2. 为什么采纳“先看开源项目”的建议

这个建议可行，而且比完全从零规划更符合工程与科研习惯。相似项目可以提供：

- 已经验证过的任务定义和输出形式；
- 最小可解释基线；
- 数据集、指标和失败场景；
- 可比较的复杂方法；
- 哪些方案在真实机器人上已经尝试过。

但正确做法不是直接复制一个效果视频或仓库，而是：

1. 先确认任务、数据视角和输出是否相同；
2. 检查许可证、环境、数据开放程度和评价协议；
3. 选择一个最小基线，再选择一个较强对照；
4. 独立实现自己能解释的版本；
5. 使用自己的开发/冻结测试协议重新评价；
6. 只有改善了预先定义的指标或失败组，才叫优化。

以后开始实战项目时，默认加入这一步，但把候选控制在3到7个，避免无限检索。

## 3. Day59 审查了哪些开源参考

```text
projects/04_crop_row_perception/docs/open_source_baseline_review.md
```

核心结论如下。

### 3.1 最接近当前能力的经典基线

[petern3/crop_row_detection](https://github.com/petern3/crop_row_detection) 使用 OpenCV、`2G-R-B` 植被增强和 Hough 思路。它适合帮助我把已学的颜色空间、阈值、形态学和直线检测连接起来。

但其 README 同时说明大约只能检测50%的作物行，并存在三行偏好、弯曲行和作物颜色/密度限制。因此它只能是“需要重新评价的起点”，不是成熟答案。仓库为 GPL-3.0，本项目不复制其代码。

### 3.2 主要评价设计参考

[Agricultural-Robotics-Bonn/visual-multi-crop-row-navigation](https://github.com/Agricultural-Robotics-Bonn/visual-multi-crop-row-navigation) 提供真实多作物导航演示、带标注数据描述，并使用作物行在图像底边的位置和方向进行评价。这与本项目的“近端位置误差 + 航向角误差”输出高度一致。

它依赖 ROS Melodic、旧版 OpenCV 和完整机器人系统，因此 Day59 只借鉴评价思想，不接入 ROS。

### 3.3 首要待审查数据候选

[JunfengGaolab/CropRowDetection](https://github.com/JunfengGaolab/CropRowDetection) 描述的 CRDLD v2.1 包含2000张图像、50种组合条件，涉及阴影、不同生长阶段、杂草、晴阴、断行、坡度/曲线和轮胎印。

它的场景覆盖适合作为 Day60 数据候选，但当前页面没有给出足够清楚的许可证和最高泄漏单位信息。因此今天不下载，也不把已有 Train/Test 文件夹直接视为安全划分。

截至 Day59，这个数据集尚未下载或实测，也没有完成图片/标签对应、损坏文件、许可证、重复与近重复、视频连续帧、农田/日期/相机分组、困难负样本和独立外部来源检查。因此 CRDLD 不是已经选定的数据，更不能根据仓库说明推断本项目会有良好外部泛化。

### 3.4 后续增强与强对照

- [PatD123/Crop-Lane-Detect](https://github.com/PatD123/Crop-Lane-Detect)：IPM、DBSCAN、时序平滑，可作为 Day63/65 的增强候选；
- [WoodratTradeCo/crop-rows-detection](https://github.com/WoodratTradeCo/crop-rows-detection)：YOLOv5 ROI 方法，可作为未来深度学习对照，但数据未完全公开；
- [PRBonn/visual-crop-row-navigation](https://github.com/PRBonn/visual-crop-row-navigation)：帮助理解视觉伺服系统接口，但其双相机/ROS条件超出当前范围；
- [EarlJr53/row-crop-detection](https://github.com/EarlJr53/row-crop-detection)：支持“先简单方法，再比较复杂方法”的学习节奏，但没有正式利用 CRBD 做定量基准。

## 5. 坐标系必须先统一

### 5.1 像素坐标

OpenCV 图像坐标定义为：

```text
原点：(0, 0)，位于左上角
x：向右增大
y：向下增大
```

宽度为 `W`、高度为 `H` 时，归一化坐标为：

```text
x_norm = x_px / (W - 1)
y_norm = y_px / (H - 1)
```

因此左上角映射为 `(0, 0)`，右下角映射为 `(1, 1)`。归一化后，同一算法可以比较不同分辨率的输入。

### 5.2 近点与远点

在图像中：

- `near` 位于图像下方，`y_near` 较大；
- `far` 位于图像上方，`y_far` 较小；
- 必须满足 `y_far < y_near`。

若顺序相反，航向角符号会被错误解释，因此参考代码直接拒绝这种输入。

### 5.3 归一化中心偏移

定义近端中心线位置相对相机图像中心的偏移：

```text
lateral_offset_norm = x_near_norm - 0.5
```

- 等于0：近端中心线位于图像中心；
- 大于0：目标中心线在相机中心右侧；
- 小于0：目标中心线在相机中心左侧。

它只是图像平面偏移。没有相机标定、安装姿态和地面投影时，不能称为“机器人偏了多少米”。

### 5.4 局部航向角

从近点指向远点，把向图像上方视为前进方向：

```text
dx = x_far_norm - x_near_norm
forward = y_near_norm - y_far_norm
heading_error_deg = degrees(atan2(dx, forward))
```

- 等于0：中心线竖直向前；
- 正值：中心线朝图像右上方；
- 负值：中心线朝图像左上方。

这里的角度是图像方向代理，不是尚未标定的真实世界航向误差。

## 6. 为什么必须输出拒绝状态

农业场景可能出现地头、完全遮挡、过曝、模糊、无作物行或非农田画面。算法如果始终强制输出一条线，就可能产生高置信度错误。

因此合同定义：

- `valid`：通过全部几何和质量检查；
- `degraded`：仍有可解释结果，但质量较弱；
- `reject`：没有可靠走廊或输入不受支持。

本项目把“该拒绝却输出 valid”视为最高成本错误。

## 7. 预先固定的评价指标

| 指标 | Day59 阈值 | 回答的问题 |
|---|---:|---|
| 近端位置 MAE | 不超过图像宽度的5% | 中央走廊位置是否准确 |
| 航向角 MAE | 不超过5° | 局部方向是否准确 |
| 支持帧 valid 召回 | 至少85% | 是否过度拒绝正常场景 |
| 应拒绝帧错误 valid 率 | 不超过5% | 是否输出危险的伪可靠结果 |
| 640x360 CPU 中位耗时 | 不超过50 ms | 是否具备离线实时候选速度 |

这些是目标阈值，不是今天已经达到的结果。只有后续保留的实测证据才能把它们改写为完成指标。

### 7.1 内部好不等于外部好

任何数据集都不能保证内部和外部结果都好。能提前保证的是评价纪律：如果独立外部证据没有通过，就不允许把项目称为泛化成功。

本项目要求：

1. 内部开发数据按视频序列、农田、日期、相机等最高泄漏单位分组；
2. OOD 开发数据可以用于改进，但每次迭代必须留痕；
3. 冻结外部数据必须来自独立来源，并且不能用于选择算法、阈值或置信度；
4. 内部和冻结外部都必须达到同一组绝对阈值；
5. 外部相对内部的位置 MAE 增幅不超过0.02、航向 MAE 增幅不超过3°、错误 `valid` 率增幅不超过0.03、支持帧 `valid` 召回下降不超过0.10；
6. 任一外部绝对阈值、差距规则、主要困难组、困难负样本或来源独立性失败，都阻断“泛化成功”声明。

这些规则的目标是尽量提高得到可信内外部结果的概率，并阻止重复出现“内部指标很好、外部严重失败却仍包装为成功”的问题；它们不能预先承诺实验一定成功。

## 8. 证据角色

`evidence_registry.yaml` 把证据分成：

1. 开源背景参考：只能帮助设计，不能证明我们的效果；
2. ID开发集：可以进行普通开发和阈值选择；
3. OOD开发集：用于有日志的稳健性改进；
4. 冻结外部测试：只能做最终估计，不能反向调参。

Day59 除开源背景参考外，其余三类数据均为 `NOT_AVAILABLE`，等待 Day60 审查。
