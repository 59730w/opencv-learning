## 二、为什么学习这个专题

前三个实战都出现了类似现象：模型在同来源测试集上表现很好，但面对独立来源图片时性能明显下降。

这说明当前的主要问题已经不是“代码能不能运行”或“模型能不能收敛”，而是：

> 训练集和测试集是否真正代表未来要处理的数据？模型学习的是稳定的任务规律，还是数据集中特有的背景、拍摄方式和采集痕迹？

机器学习通常假设训练数据和未来数据独立同分布，但现实中的设备、地点、时间、天气、拍摄距离、背景和使用者都会变化。因此，分布偏移不是少见异常，而是机器视觉落地时必须主动处理的问题。

## 三、核心概念

### 1. ID 与 OOD

- **ID（In-Distribution）**：数据来自与训练集相同或非常相近的分布。
- **OOD（Out-of-Distribution）**：数据在来源、场景、采集方式或类别范围等方面偏离训练分布。

可以分别记录内部指标与外部指标：

```text
ID 指标：M_ID
OOD 指标：M_OOD
泛化落差：Gap = M_ID - M_OOD
```

高 `M_ID` 只能证明模型适合同来源数据，不能自动证明真实场景中的 `M_OOD` 也高。

### 2. 常见的分布偏移

| 类型 | 含义 | 机器视觉例子 |
| --- | --- | --- |
| 输入/协变量偏移 | 输入图像分布 `P(x)` 改变 | 相机、光照、背景、季节、分辨率变化 |
| 标签比例偏移 | 类别比例 `P(y)` 改变 | 训练集各树种均衡，真实林区少数树种占多数 |
| 概念偏移 | 输入和标签的关系 `P(y\|x)` 改变 | 环境或任务定义变化导致旧规律失效 |
| 子群体偏移 | 某些少数场景在训练集中不足 | 雾天烟雾、幼树、破损树皮、小目标宠物 |
| 开放集偏移 | 出现训练类别以外的输入 | 未知树种、非树皮图片、没有宠物的场景 |

### 3. 数据集偏差

所有有限数据集都只是现实世界的一个有偏样本。常见来源包括：

- **摄影者偏差**：人们喜欢使用典型视角、清楚构图和容易识别的距离拍摄。
- **采集偏差**：网络搜索图、实验室图片、监控视频和手机照片的视觉风格不同。
- **标注偏差**：标注规则、人员理解和模糊样本处理方式不同。
- **社会偏差**：数据采集可能不均衡地代表地区、人群或使用环境。
- **测试与基准偏差**：在固定测试集上反复调参，会逐渐对测试集本身过拟合。

如果人或分类器可以仅凭图像风格判断图片来自哪个数据集，说明数据源中存在明显的“来源特征”。模型也可能利用这些来源特征，而不是学习真正稳定的目标特征。

### 4. 捷径学习

神经网络会优先学习容易降低训练损失的预测模式，但容易利用的模式不一定是我们真正希望它学习的规律。

例如：

- 烟雾检测器可能学习某种天空颜色或数据集水印。
- 宠物分割器可能把毛绒纹理或复杂物体边缘当成宠物前景。
- 树皮分类器可能学习拍摄距离、背景、文件序列或相机风格。

这些捷径在同来源划分中仍然有效，因此验证指标可能很好；当数据来源变化后，捷径失效，OOD 性能就会快速下降。

## 四、为什么增加同来源数据不一定解决问题

如果新增图片仍来自相同的相机、地点、拍摄人员和采集流程，它们可能只会让模型更熟悉原有偏差。

真正有价值的数据应当更接近目标分布。与目标域差异很大的样本，即使数量很多，也可能不如少量目标域样本有效。

因此，数据建设不仅要问“有多少张”，还要问：

1. 来自多少独立来源？
2. 覆盖哪些地点、设备、时间和天气？
3. 是否包含困难正样本、真实负样本和未知类别？
4. 是否能按对象、个体、地点或采集批次隔离划分？

## 五、提高鲁棒性的方法

### 1. 优先获得更有代表性的数据

最直接的方法是让训练数据覆盖未来测试环境。模型结构和复杂算法不能替代目标场景中缺失的数据。

正确顺序通常是：

```text
定义目标分布
→ 检查数据覆盖范围
→ 补充独立来源数据和困难样本
→ 设计防泄漏划分
→ 再考虑模型和算法
```

### 2. 防止数据泄漏

不能只随机划分图片，应优先按照最高泄漏单位进行分组：

```text
同一对象/树木个体
→ 同一视频或连续拍摄序列
→ 同一地点或设备
→ 同一数据来源
→ 最后才是单张图片
```

如果同一对象的相似图片同时进入训练集和测试集，测试结果可能只是证明模型见过相似画面。

### 3. 区分三种评估数据

| 数据 | 用途 | 是否允许据此调参 |
| --- | --- | --- |
| ID 验证集 | 调试和普通模型选择 | 允许 |
| OOD 开发集 | 针对独立来源改进泛化 | 允许，但要记录每次实验 |
| 冻结外部测试集 | 最终、相对无偏的验收 | 不允许 |

最终外部测试失败后，不能继续围绕同一测试集反复修改模型。应分析失败条件，补充新的训练和 OOD 开发数据，并为下一版准备新的冻结测试集。

### 4. 数据增强

数据增强通过变换训练样本扩大训练分布，例如：随机裁剪、翻转、颜色扰动、模糊、噪声和压缩。

分类任务通常要求增强前后标签保持不变：

```text
y(x) = y(T(x))
```

但增强必须符合任务语义。例如，普通场景分类可能允许水平翻转，字符识别中的镜像却可能把 `b` 变成类似 `d` 的形状。

检测和分割中的空间变换还必须同步修改框或掩膜，这属于等变关系：输入几何发生变化，输出标注也应发生对应变化。

数据增强能够缓解已知的外观变化，但有三个边界：

1. 它不能自动生成训练数据中从未出现过的真实目标域。
2. 不合理增强可能破坏标签语义。
3. 只增强颜色和几何，不能解决错误标签、未知类别和来源泄漏。

### 5. 对抗训练与 DRO

- **对抗训练**：训练模型应对会造成较大损失的输入扰动，使输出对某些非稳定特征更不敏感。
- **DRO（Distributionally Robust Optimization）**：不只优化训练分布上的平均损失，而是考虑训练分布附近一组可能分布中的较差情况。

DRO 可以帮助模型关注少数子群体或困难条件，但它仍然依赖我们如何定义“可能出现的分布”。如果真实目标域完全不在假设范围内，算法也无法凭空保证泛化。

### 6. 其他方向

- 使用地点、季节等先验信息处理子群体偏移。
- 在存在目标域数据时使用域适应方法。
- 使用更广泛的预训练模型获得更通用的特征。
- 建立错误分层统计，明确模型在哪些来源和条件下失败。
- 对开放世界输入增加负样本、未知类或拒识机制。

## 七、以后建立视觉项目的流程

### 阶段一：先定义目标分布

- 输入究竟是近距离树皮、整棵树，还是林区视频？
- 使用什么设备、距离、天气、季节和背景？
- 支持哪些类别？遇到未知输入应如何处理？
- 哪种错误代价最高？

### 阶段二：判断数据集是否可用

- 数据是否真的覆盖目标分布，而不只是类别名称相同？
- 是否有对象、地点、设备和采集批次信息？
- 是否能建立来源独立的 OOD 开发集与冻结外测？
- 是否包含真实负样本和未知类别？

### 阶段三：低成本试验

- 先用小模型和少量数据验证完整链路。
- 同时查看 ID 与 OOD 开发指标。
- 优先修正数据覆盖、标签和划分，再增加模型复杂度。

### 阶段四：正式训练与验收

- 记录不同来源、条件和类别的指标。
- 完成错误分析、置信度分析和负样本测试。
- 最后才运行冻结外部测试集。
- 如未规定项目标准，可把 OOD 指标下降超过 10 个百分点视为预警，超过 20 个百分点视为严重阻断；这只是学习项目的启发式规则，不能替代具体任务标准。

## 八、四个关键问题

### 1. 什么是同分布测试和外部分布测试？

同分布测试使用与训练数据来源和采集方式相近的数据，主要检验模型在已知分布上的泛化。外部分布测试使用独立来源、设备、地点、时间或场景的数据，检验模型面对真实分布变化时是否仍然有效。

### 2. 数据泄漏为什么会让内部指标虚高？

因为训练集和测试集可能包含同一对象、同一序列或高度相似的画面。模型只需记住对象特征、背景或采集痕迹，就能在测试集上获得高分，但这些线索在新来源中并不存在。

### 3. OOD 开发集和冻结外部测试集有什么区别？

OOD 开发集可以用于分析和优化模型；冻结外部测试集只用于最终验收，不能参与模型、阈值、增强策略和训练轮数选择。否则它会逐渐变成另一个开发集，失去无偏评估作用。

### 4. 实战三如果重新开始，最先应改变什么？

不是先换成更大的模型，而是先重新定义目标场景并选择有来源、树木个体、地点或采集批次信息的数据。然后按最高泄漏单位划分，提前建立独立 OOD 开发集，加入未知树种和非树皮负样本，再训练基线。

## 九、今日总结

1. 内部高指标不等于真实场景可靠。
2. 所有数据集都存在偏差，必须明确数据从哪里来、缺少哪些场景。
3. 神经网络可能通过捷径完成同来源测试，而没有学到稳定规律。
4. 数据增强扩大训练分布，但不能替代真实、多来源、代表性的目标域数据。
5. 防泄漏分组、OOD 开发集和冻结外测必须在训练前设计。
6. 面向真实机器视觉时，负样本、未知类别和拒识能力不是可选项。
7. 先解决数据和评估问题，再考虑更大模型、域适应或 DRO。
