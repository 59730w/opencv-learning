## 第一阶段：Python + OpenCV + 深度学习入门

**建议时间：** 4～6 周  
**阶段目标：** 能用 Python 跑通一个森林图像识别 Demo。

### 1. OpenCV 部分

| 模块 | 学习内容 | 与森林监测的关联 |
|---|---|---|
| 核心操作 | 图像读写、色彩空间、ROI | 树种拍摄、光照修正 |
| 图像处理 | 滤波、边缘检测、形态学 | 树木轮廓提取 |
| 特征 | SIFT/ORB、模板匹配 | 树种特征匹配 |
| 目标检测 | Haar 级联、HOG | 理解早期传统方法 |

**资源建议：** 在 B 站搜索“贾志刚 OpenCV Python”，选择上述模块学习，其他内容暂时跳过。

### 2. 深度学习部分（重点投入）

主线课程：李沐《动手学深度学习》PyTorch 版（B 站），学习前 8 章。

重点学习方向：

```text
CNN → 图像分类 → 目标检测（YOLOv8）→ 图像分割（U-Net）
```

### 3. 森林相关 Demo

使用公开数据集完成一个森林相关项目，例如：

- 树种分类；
- 植被覆盖度分割。

> 🎯 这个 Demo 非常重要。入学后可以直接向导师展示，用来证明自己的自学能力和基础。

### 4. 课程观看范围

| 集数 | 安排 | 内容说明 |
|---|---|---|
| 第 1～99 集 | ✅ 学习 | 前 7 章，约 50 小时内容 |
| 第 100～110 集 | ❌ 暂时跳过 | 多 GPU、分布式，现阶段暂时用不上 |
| 第 111～117 集 | ✅ 学习 | 数据增广、微调、树叶分类竞赛 |
| 第 118～121 集 | ◻️ 选看 | 两个 Kaggle 竞赛，可选择性学习 |
| 第 122～144 集 | ✅ 学习 | 目标检测与语义分割 |
| 第 149～173 集 | ❌ 跳过 | RNN 相关内容 |
| 第 174～197 集 | ⏸️ 搁置 | Transformer/BERT，入学后再学习 |

### 5. 建议学习节奏

考虑到缓冲时间和 Demo 制作时间，建议按以下节奏推进：

1. **第 1～78 集（前 6 章）：** 每天学习 4～5 集，约 15 天完成。
2. **第 79～99 集（第 7 章现代 CNN）：** 每天学习 4～5 集。该部分信息密度较大，约 4 天完成。
3. **第 111～144 集：** 与 YOLO、U-Net 和森林识别 Demo 实战交替进行。

## 第二阶段：C++ 补强

**建议时间：** 4～6 周  
**阶段目标：** 能用 C++ 编写 OpenCV 程序，并理解编译流程。

> 这是区别于纯 AI 方向同学的核心竞争力。

| 学习内容 | 学习重点 | 资源推荐 |
|---|---|---|
| C++ 基础 | 指针、引用、STL、智能指针 | 黑马程序员 C++（B 站） |
| OpenCV C++ | 复用已掌握的视觉算法，重点学习 `cv::Mat` 内存语义、C++ 接口设计和工程化 | 贾志刚 C++ 版 + OpenCV 官方文档 |
| CMake | 必须掌握，所有嵌入式项目的标配 | CMake 官方教程 |
| 编译流程 | `gcc`/`g++`、交叉编译概念 | 搜索“交叉编译入门” |

**当前进度（2026-08-30）：**

- Day44：完成 MSYS2 UCRT64、CMake/Ninja、OpenCV 5 工具链和首个 C++ OpenCV 程序。
- Day45：完成真实图片 I/O、HighGUI、`cv::Mat` 浅/深拷贝、`const cv::Mat&` 和退出码验收。
- Day46：完成 C++17 `std::filesystem` 目录遍历、`cv::imread` 批量读取与单文件失败隔离、`struct`+`std::vector` 结果汇总和退出码验收。
- Day47：完成批量图像处理与结果落盘——`cv::cvtColor` 灰度转换、`cv::imwrite` 落盘、读/写双重失败隔离、`create_directories` 输出目录管理。
- Day48：完成 `std::unique_ptr` / `std::shared_ptr` 所有权练习，并将批处理器升级为支持 `--op gray|blur|edge` 的可配置处理管线，完成自动契约测试和退出码验收。
- Day49：完成 Debug 构建、GDB 源码断点/变量/调用栈与受控异常定位，并使用 `objdump`、`where.exe` 和 `info sharedlibrary` 分析 Windows 运行时 DLL 依赖。
- Day50：将单文件图像处理管线重构为 `ImagePipeline` 类和头源分离工程，使用 CMake 构建静态库与可执行程序两个目标，并以 35 项契约测试验证封装边界、三种处理模式和退出码。
- Day51：为图像处理管线增加顺序与 `std::thread` 多线程模式，使用原子索引、线程回收和异常回传保证并发安全，以 `steady_clock` 计时并通过 71 项契约测试验证输出哈希一致性；在32张图片的受控基准中记录1/2/4线程结果与限制。
- Day52：使用 CTest 统一运行 C++ 单元测试和 PowerShell 契约测试，完成 CMake 安装、导出 `day52::pipeline`、独立消费者验证与 CPack 开发包检查。
- Day53：将森林树种 ResNet18 从 PyTorch 检查点导出为动态批次 ONNX，使用 ONNX Runtime 对 batch=1/2/3 的真实图片进行数值与 Top-k 一致性验证，并记录 PyTorch 2.5 Dynamo 动态导出的兼容性边界。
- Day54：在 MSVC/CMake 中接入 ONNX Runtime 1.19.2 与 OpenCV 4.10.0，完成模型接口检查、C++ 预处理、动态 batch=1/3 推理、类别映射和 Top-k 输出；四项 CTest 全部通过，并将同张量运行时一致性与 OpenCV/PIL 端到端预处理差异分开验收。
- Day55：完成 ONNX Runtime C++ CPU 受控性能基准，严格区分纯 `Session::Run` 与端到端计时，比较 batch=1/3/6 和 ORT 默认/单线程配置，保留120条原始测量与12组汇总，并通过回归测试修正计时边界和 Session 创建时间留存问题。
- Day56：完成 ONNX Runtime C++ Profiling，使用独立预热 Session 和3组受控配置定位 CPU 算子热点，过滤 Session/fence 事件并汇总带 Provider 的 Node 事件；两项 CTest 通过，Batch6 两种线程配置相对 Day54 的 logits 误差为0且有序 Top-3一致，确认当前主要热点是卷积算子。
- Day57：完成 ONNX Runtime QDQ S8S8 静态 INT8 量化，使用训练集200张均衡图片校准；模型缩小74.719%，validation/test Accuracy 与 Macro-F1 下降均小于1个百分点，但受控 C++ CPU 基准显示 Batch1/6 均慢于 FP32，因此仅保留为体积压缩实验，不宣称加速或泛化改善。
- Day58：用预注册的单变量实验比较 ORT 默认/单线程下 FP32 与 QDQ S8S8 INT8 的 Batch1/6 性能；240条 runtime-only 计时和跨线程输出一致性表明，默认并行对FP32的收益显著高于INT8，足以解释本机上的相对慢速，但显式单线程使两种模型绝对延迟均恶化数倍，因此不是部署优化，也不改变外部泛化与开放集失败结论。
- 后续不重复 Day1～Day15 的 Python OpenCV 基础操作；继续在正确性等价门通过的前提下学习模型优化、硬件后端与嵌入式部署。

## 第三阶段：嵌入式平台上手

**建议时间：** 3～4 周  
**阶段目标：** 在真实硬件平台上运行视觉项目。

结合森林场景，可能使用的硬件平台如下：

| 平台 | 可能性 | 学习重点 |
|---|---:|---|
| NVIDIA Jetson Nano/Orin | ⭐⭐⭐⭐ 最高 | TensorRT + DeepStream |
| 树莓派 4/5 | ⭐⭐⭐ | OpenCV + TFLite / ONNX Runtime |
| STM32 + 摄像头 | ⭐⭐ | STM32Cube.AI / TinyML |

> 💡 如果暂时不确定购买哪个平台，可以先买树莓派。它价格相对较低，能够跑通完整的嵌入式与计算机视觉流程，作为入门平台已经足够。

## 第四阶段（入学后）：切入导师方向

**阶段目标：** 阅读论文、理解课题组技术路线并确定研究课题。

入学后可以按以下顺序推进：

1. 搜索导师近 3 年发表的论文，精读其中 2～3 篇。
2. 了解并跑通课题组使用的代码基线。
3. 关注林业计算机视觉的前沿方向：
   - 遥感图像分割；
   - 树种识别；
   - 碳储量估算；
   - 边缘 AI 推理优化。
4. 向师兄师姐获取代码仓库，先跑通现有代码，再尝试修改与改进。
